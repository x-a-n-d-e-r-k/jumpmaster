Which accounts

Recommended: Two bot accounts as GitHub Apps: an author app and a reviewer app.

Use two GitHub Apps: an author app and a reviewer app, registered under the repository's owner and installed on the repository. There are no tokens to make or renew: each app signs in with a short-lived token Jumpmaster asks GitHub for. Neither app is an admin, so the ruleset guards every merge. To use tokens instead, the organization must allow fine-grained tokens (the organization's Settings → Personal access tokens → Settings) and may have to approve each token.

Create the tokens

Each link opens GitHub's fine-grained token page, filled in. For each token:

  1. Sign in as the account the token is for, then open its link below. Make a new token here rather than reusing one made for another tool or install: an older token may have expired, and its permissions may not fit. If this install already has this account's token, edit its repository access instead (the next step).
  2. Resource owner: check the Resource owner field: for an organization it may not pre-fill, and the link may set only what it shows, so re-select the organization even when it looks selected.
  3. Repository access: choose Only select repositories, then the repository (the link cannot choose it). For another project later, edit this token's repository access on GitHub to add it: no new token, and no account-wide access.
  4. Click Generate token.
  5. Paste it into Jumpmaster's GitHub step: it is tested before it is saved, and never shown back.

Expiry: each link asks for 90 days; an organization's token lifetime policy may cap it at less, and the doctor warns two weeks before a token expires.

  • The author token (the account that opens and merges pull requests)
    Contents: Read and write · Pull requests: Read and write · Issues: Read and write · Metadata: Read-only · Commit statuses: Read-only · Actions: Read-only; no Workflows, no Administration.
  • The reviewer token (a second account, which approves them)
    Pull requests: Read and write · Contents: Read-only · Metadata: Read-only; no Workflows, no Administration.

The branch ruleset

missing no ruleset <b>protects</b> main

Jumpmaster merges only under a ruleset that requires a pull request and your CI, with no bypass. This file is one, with the checks your workflows report, and a code owner's review on the protected paths:

  1. Open the repository's Rulesets, then New ruleset → Import a ruleset, and choose jumpmaster-demo-ruleset.json.
  2. Review it and click Create.

A matrix job reports one check per combination, such as build (ubuntu-latest), and a reusable workflow's jobs report as caller / inner: check the exact names on a pull request's Checks tab and correct the required checks to match.

Download jumpmaster-demo-ruleset.json 

{
  "name": "jumpmaster",
  "target": "branch",
  "enforcement": "active",
  "bypass_actors": [],
  "conditions": {
    "ref_name": {
      "include": [
        "~DEFAULT_BRANCH"
      ],
      "exclude": []
    }
  },
  "rules": [
    {
      "type": "pull_request",
      "parameters": {
        "required_approving_review_count": 1,
        "dismiss_stale_reviews_on_push": true,
        "require_code_owner_review": true,
        "require_last_push_approval": false,
        "required_review_thread_resolution": false
      }
    },
    {
      "type": "required_status_checks",
      "parameters": {
        "strict_required_status_checks_policy": false,
        "required_status_checks": [
          {
            "context": "test",
            "integration_id": 15368
          }
        ]
      }
    }
  ]
}

Code owners for the protected paths

check no CODEOWNERS file

Changes to the protected paths need a person's review. Name yourself (and anyone else who may approve them) as code owners: each needs the Write role.

The file starts with the reviewer bot on *, so its approval still merges ordinary pull requests. If your file already has a * line, add the reviewer bot to it, or nothing will merge.

Create .github/CODEOWNERS on GitHub, paste the text, and commit it. 

# Jumpmaster zone demo: changes to these paths need a human code owner's review.
# The reviewer bot owns everything else, so its approval merges an ordinary pull request; the lines after this one give the protected paths back to people.
* @jm-reviewer
